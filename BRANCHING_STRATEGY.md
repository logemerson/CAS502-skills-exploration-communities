# Git Branching Strategy

## Our Approach
Both team members will primarily commit to the main branch for this project. Given the small team size and the focused scope of our enhancement (adding community detection), we want to keep things simple and avoid unnecessary complexity.

## When We Will Use Branches
If we are working on a larger feature that might break existing functionality, we will create a feature branch (e.g., feature/community-detection). Once the feature is complete and tested, we will merge it back into main.

## Pull Requests
We will use pull requests when merging feature branches into main. This gives the other team member a chance to review the changes before they are merged.

## Merge Strategy
We will merge branches once the feature is complete and has been reviewed by the other team member. We will delete feature branches after merging to keep the repository clean.
